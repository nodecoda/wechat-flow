# 立意规范（Intent Cards）

**触发**：Step 2.5（选题后、框架前）。**核心命题**：立意是文章的 DNA——没有立意的文章是"正确的废话"，有了立意，结构、素材、修改才有所依附。

**判定关系**：角度（怎么切）≠ 立意（判断什么）。角度可以有多个候选，立意一篇只能有一个主判断。

## 1. 立意的四种形态

| 形态 | 判断句模板 | 适用时机 |
|------|-----------|---------|
| **反转** | "主流说 X 好，但 X 有致命问题" | 共识存在明显漏洞 |
| **升维** | "大家在争 A vs B，但这个问题本身问错了" | 讨论框架本身过时 |
| **预测** | "短期看 X，三年后是 Y"（或反向） | 事件刚发生，多数人只看眼前 |
| **筛选** | "不是所有人都该用 Y——X 情况用 Y，Z 情况用 W" | 方法论类、干货类内容 |

示例（角度 → 立意）：
- 角度：从反直觉切入
- 立意：「传统 SaaS 会被 Agent 杀死，因为交付方式从卖工具变成卖结果」
- 信息差：读者以为「AI 是 SaaS 的增强」，读完应知道「AI 正在替换 SaaS 的计费单元」

## 2. 立意产生的五步心智过程

```text
① 浸泡（素材喂观点，不是观点找素材）
   → ② 直觉（产生模糊"感觉"：这事不对劲 / 有意思）
   → ③ 提炼（把感觉压成一句判断句，先允许粗糙）
   → ④ 检验（信息差 / 可信度 / 边界 三问）
   → ⑤ 定型（主立意 1 个 + 支撑判断 ≤3 个）
```

| 步骤 | 动作 | 失败症状 |
|------|------|---------|
| ① 浸泡 | 采集足够素材，观点从素材里长出来 | 素材不足就下判断 → 立意空转 |
| ② 直觉 | 捕捉"不舒服/反常识/值得说"的瞬间 | 无直觉 → 立意平庸（复述已知） |
| ③ 提炼 | 压缩成一句话，删掉所有修饰 | 说不清 → 没想清 |
| ④ 检验 | 三问校验（见 §3） | 跳过检验 → 立意站不住 |
| ⑤ 定型 | 锁定主立意 + 边界 | 主立意漂移 → 全文散 |

## 3. 立意检验三问

立意写完后必须过三问。任何一问不过，返回上一阶段：

| 问 | 判定标准 | 不通过的表现 |
|----|---------|------------|
| **信息差**："读者现在以为 X，读完应该知道 Y，X→Y 的差距在哪？" | 差距明确且值得 | "这谁不知道" |
| **可信度**："读者凭什么信我？" | 有数据/案例/经历支撑 | 全靠形容词和情绪 |
| **边界**："什么情况下我这个判断不成立？" | 能主动说出反例 | 全称判断、无限上纲 |

**机器可判部分**由工具执行：

```bash
python3 {skill_dir}/toolkit/intent.py validate output/{slug}-intent.yaml [--blacklist "词1,词2"]
```

- 信息差：`info_gap.from != to` 且均非空
- 可信度：`evidence` 非空（Phase D 起由 FactSheet 预填）
- 边界：`boundary` 非空
- 黑名单：thesis/topic 命中 `style.yaml` 的 `blacklist` → 直接淘汰
- 选题相关 / 候选完整性：软校验（不阻断）

## 4. 候选立意生成提示词（Agent 用）

对每个候选，按形态套用：

```text
基于选题「{topic}」和素材（见 evidence），生成一个{形态}判断句：
- 一句话，删掉所有修饰
- 有立场（不是综述，是判断）
- 可证伪（能被反驳，说明有信息量）
- 附上支撑该判断的 1 条素材编号
```

生成 3-5 个候选写入 `thesis_candidates`；**终审（人/Agent）选中最尖锐且有支撑的一个**写入 `thesis`。

## 5. IntentCard 字段释义

```yaml
topic: 选题（必填，scaffold 时写入）
thesis: 主立意判断句（终审后写入）
angle: 反转 / 升维 / 预测 / 筛选
thesis_candidates: [候选判断句]   # Agent 生成，人终审
info_gap: {from: 读者起点认知, to: 读后应知}
evidence: [{claim, source, url}]  # 与 FactSheet 共享条目
boundary: 判断不成立的条件
title_candidates: [标题候选]      # intent.py titles 生成，Step 5 打磨
status: generated → user_confirmed → locked
```

## 6. 立意与相邻环节的关系

```text
选题 → 立意(本文件) → 框架(frameworks.md) → 写作(表达) → 修改(revision，以 thesis 为校验基准)
                              ↑                                  │
                              └──── 修改时发现立意漂移 → 回到立意定型 ──┘
```

- **对框架**：先有立意再选结构——框架是立意的论证结构（7 框架本质是 7 种论证方式）
- **对写作**：thesis 贯穿每个 H2（content-enhance 已要求"论点贯穿全文"，此处给出显式依据）
- **对修改**：`revision.py analyze --intent` 用 thesis 的二元组检查各 H2 节是否偏离
- **对标题**：好立意自然长出好标题；`intent.py titles` 给出规则模板，再按 seo-rules.md 打磨

## 7. 失败模式与降级

| 失败模式 | 症状 | 处理 |
|---------|------|------|
| 立意平庸（无信息差） | 三问第一问不过 | 回五步法②③重找直觉；两次不过 → 换选题 |
| 立意过强（支撑不足） | 可信度问不过 | 回备料期补素材；补不上 → 收窄立意 |
| 立意漂移（写着写着跑了） | 修改时结构层检出 | 回定型，或重写跑偏段落 |
| 立意与人格冲突 | 判断句语气与 persona 不符 | 保留立意、重写判断句的语气外壳 |
| intent.py 缺失 | 老安装 | 回退 content-enhance.md 角度发现（LLM 直出，不落盘） |
