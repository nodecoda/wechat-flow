# 修改规范（Revision Guide）

**触发**：交互模式；或用户说"修改"/"改一下"/"润色"；或 Step 5.3 复检不通过时。

**总则**：初稿是把话说出来，修改是把话说好。修改必须**从大到小**（结构→段落→句子→措辞），否则在句子上精雕细琢、回头发现段落要删，是纯浪费。

## 1. 四层修改模型

### 1.1 结构层（删 / 调 / 重组）—— 优先级最高
| 检查项 | 问题 | 操作 |
|--------|------|------|
| 立意贯穿 | 每段是否服务主立意？（用 IntentCard 做基准） | 删偏离段 / 重写 |
| 主线清晰 | 读者能否一句话说出文章逻辑？ | 调整段落顺序 |
| 冗余段落 | 删掉某段，文章是否不受影响？ | 删 |
| 首尾呼应 | 结尾是否回扣开头钩子/立意？ | 补或调 |
| 框架忠实 | 是否按所选框架的论证结构展开？ | 对照 frameworks.md |

### 1.2 段落层（改 / 并 / 拆）
| 检查项 | 问题 | 操作 |
|--------|------|------|
| 逻辑链 | 段间是否有隐含的"所以/但是/换句话说"？ | 补转场 / 重排 |
| 单段职责 | 一段是否只讲一件事？ | 拆分 |
| 信息密度 | 干货段是否可操作（"5 分钟内能动手"）？ | 补具体步骤/参数 |
| 节奏 | 长段后是否紧跟短段？ | 调节段落长度交替 |

### 1.3 句子层（节奏 / 可读性）
| 检查项 | 问题 | 操作 |
|--------|------|------|
| 长度变化 | 是否连续 3+ 句长度接近？ | 拆长句 / 并短句 |
| 破句与口语 | 是否有人味（破句、自我纠正）？ | 按 persona 注入 |
| 信息顺序 | 句内重点是否前置？ | 调整语序 |
| 被动/名词化 | 是否绕口？ | 改主动、改动词 |

### 1.4 措辞层（字词）—— 优先级最低
| 检查项 | 问题 | 操作 |
|--------|------|------|
| 空话 | "总而言之/值得注意的是"类套话 | 删（revision.py apply 自动） |
| 精确 | 用词是否可更准？ | 替换 |
| 重复 | 同词/同构句高频复现 | 换词 |
| 一致 | 术语、人称、数字单位是否统一 | 统一（全/半角、引号自动） |

## 2. 工具用法

```bash
# 四层静态检查 → output/<slug>-revision.yaml
python3 {skill_dir}/toolkit/revision.py analyze {article_path} [--intent output/<slug>-intent.yaml]

# 措辞层一键自动修复（空话/全角数字/重复标点/重复行）——改前自动备份
python3 {skill_dir}/toolkit/revision.py apply {article_path} [--dry-run]

# 改后复检：证明"修改让文章变好"（baseline vs after）
python3 {skill_dir}/toolkit/revision.py recheck {article_path}

# 回滚（after 明显劣化时）
python3 {skill_dir}/toolkit/revision.py rollback {article_path}
```

> revision.py 是**修改脚手架**：机械部分（措辞层）自动执行；句子/段落/结构层的判断与拍板由你/Agent 完成。

## 3. 优先级与停止条件

### 优先级
```text
结构问题 > 段落问题 > 句子问题 > 措辞问题
（从大到小，否则白改）
```

### 停止条件（改到什么程度算好）
1. 无结构层问题（立意贯穿、主线清晰、无冗余段）
2. 无重复（词级 + 结构级）
3. 有金句（至少 1 句可摘录，revision.py 会标候选）
4. 朗读通顺（无卡壳点）
5. 复检不劣化（recheck 的 after 不高于 baseline，或 ≤ +2 可接受）

## 4. 与现有机制的关系

| 机制 | 归属 | 关系 |
|------|------|------|
| `humanness_score.py` | 检测器 | 打分 ≠ 修改。它指出"哪里像 AI"，本规范负责"怎么改" |
| `revision.py` | 脚手架 | 四层检查 + 措辞层自动 + 复检/回滚闭环 |
| `learn_edits.py` | 学习器 | 学习人的修改 → 反哺规则库（"这类文章用户总爱删开头"） |
| `writing-config.yaml` | 参数源 | 若复检持续不达标 → 调参再写，而非反复打补丁 |

## 5. 失败模式与降级

| 失败模式 | 症状 | 处理 |
|---------|------|------|
| 只改表层 | 措辞改完，结构问题还在 | 强制按四层顺序，结构层不过不进入下一层 |
| 过度修改 | 初稿"活气"被磨平（复检反而变差） | 每层限 1 轮；复检劣化 → rollback |
| 修改引入新错 | 事实/一致性被改坏 | 事实类修改对照 FactSheet 出处 |
| 无金句 | 全文平淡 | 立意阶段应已预埋金句位（frameworks.md 金句预埋），此处只验收 |
| revision.py 缺失 | 老安装 | 回退到纯人工四层检查 + humanness_score 打分 |
